# Project Rules: Local-First PBS Workflow

Read this file before inspecting, changing, or running project code.

- The local checkout is authoritative. Use `LOCAL_CONDA_ENV` for lightweight local tests; use the configured SSH host, `REMOTE_CONDA_ENV`, and PBS queue for substantial GPU and long jobs. Never train on a login node.
- Read this project's `.workflow/config.env` before every operation: it is executable trusted shell and the sole configuration source. Reuse its existing binding automatically; never copy project settings back into the global skill template. Fill missing host, absolute base directory, stable `PROJECT_SLUG`, and environment/queue settings from existing configuration or user input. Verify `REMOTE_HOST:REMOTE_BASE_DIR/PROJECT_SLUG` and avoid accidental remote-directory sharing. If required values are missing, report that binding is pending. Confirm queue resource and walltime limits; template values are examples. Store no secrets here.
- Prefer the project's `scripts/remote-workflow`; without a project argument it uses its own project root, regardless of the current directory. Select only the requested operation: `doctor`, `sync`, `submit`, `status`, `pull`, `github-check`, or `github-stage`. `submit` always syncs again. Initialize new projects from the full skill package with an explicit target; review their sync/retrieval lists. Initialization/binding alone does not authorize transfers, submission, background watchers, or recurring sync.
- `init` saves a stable slug for a new configuration and preserves existing files; repeating it does not rebind or upgrade. Local folder moves/renames preserve the saved remote binding. Copies intended as new projects require a new explicit slug/destination and review of copied checkpoints and `DONE_FILE` before running.
- Before a formal run: inspect code/configuration/output paths, perform local checks, preview transfers, and run a small PBS smoke test where practical.
- Before every Agent-performed transfer, inspect the complete dry-run list and per-file bytes. Never transfer a file >= 10 MiB (10,485,760 bytes) as an Agent: provide the user an exact command with source/destination/size and verification instead. Use resumable downloads. Smaller required files can transfer automatically to known destinations; report and verify them. CLI execution itself does not enforce this Agent-only threshold.
- Preserve `.workflow/sync-exclude.txt` protections, inspect deletion effects, and exclude any additional private data. Code moves through SSH/rsync. `.workflow/important-results.txt` selects results to retain locally.
- For queued/waiting jobs or expected runtimes above five minutes, stop polling and hand off: give exact job ID, remote/log/checkpoint/result/completion paths, and resolved queue/log/artifact commands. A missing `qstat` entry does not prove success.
- Work exceeding one slice uses the supplied `afterany` chain. Save atomic checkpoints each epoch and on SIGTERM/SIGINT; include model, optimizer, scheduler/scaler, epoch/step, RNG, and essential trainer/sampler state. Resume the next unfinished step automatically. After fatal deterministic errors, verify that continuation stopped: the script's `qdel` cancellation is best-effort. Inspect queue and logs; some setup failures do not write `TRAINING_FAILED`.
- Write the configured `DONE_FILE` only after training and required result validation succeed. Check logs, checkpoints, results, and marker together. Do not discard an existing checkpoint or marker without understanding it.
- Use `configs/`, `src/`, `scripts/`, `tests/`, `pbs/`, and `docs/` for their usual purposes. Experiment artifacts go in `outputs/{checkpoints,logs,results,reports,figures,status}/`; paper figures and generation scripts go in `results/`; temporary files go in `tmp/`.
- `data/raw/` is immutable. Keep one canonical result, preferably readable JSON. Overwrite derived results unless preservation is requested; inventory/classify files before deleting or reorganizing them.
- GitHub is optional. Only publish when requested or already established. Run `github-check`, inspect whitelist/staged content, and apply the separate 99 MiB guard and the 10 MiB Agent transfer rule. Never commit credentials, keys, `.env`, private/raw data, or files >= 100 MiB. Do not create repositories or force-push without explicit authorization.
- Report exact commands, output paths, job IDs, and completion evidence; derive project roots and keep scripts portable with `set -euo pipefail` where appropriate.
